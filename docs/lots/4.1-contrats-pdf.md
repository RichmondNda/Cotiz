## Périmètre

### Tables créées

Définition cible dans [`specs/schema.sql`](../specs/schema.sql) (rechercher `lot 4.1`), dictionnaire dans [`specs/data-model.md`](../specs/data-model.md).

- `contract_signatures` — Contre-signature d'un souscripteur, avec éléments de preuve.

## Étapes

Une étape = une PR. Commande : `/etape 4.1 <n>`.

### Étape 1 · Tables

`contracts`, `contract_signatures` (trigger de verrouillage, ajout seul).

**Vérification :** Tests d'invariants

### Étape 2 · Éditeur

`ct.get` (lecture, `PUT` du modèle, verrouillage avec signature de l'association), `ct.list`.

**Vérification :** `contract_locked` après verrouillage

### Étape 3 · Signature

`me.contract` (texte rendu + SHA-256), `me.sign` (empreinte comparée, consentement), inscription `active`, échéancier généré ; `signature_required` avant toute déclaration si le projet l'exige.

**Vérification :** `contract_changed` testé

### Étape 4 · PDF

`packages/pdf-templates` (contrat + page de preuve) ; worker `documents` → Gotenberg → `cotiz-legal` (WORM) ; `me.contracts`.

**Vérification :** PDF identique octet pour octet à chaque téléchargement

## Intégration front

- Onglet contrat du projet, écran de signature, listes des contrats (gestionnaire et souscripteur).
- Basculer les endpoints du lot avec `/bascule <id>` : `me.contract`, `me.sign`, `me.contracts`, `ct.get`, `ct.list`.
