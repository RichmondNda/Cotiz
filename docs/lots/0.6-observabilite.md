## Objectif

Instrumenter le code dès le départ pour voir ce qui se passe en local. Le raccordement à la pile d'observabilité hébergée (ELK, Grafana, GlitchTip, Uptime Kuma, ntfy) se fait au lot 7.1, avec la recette.

## À lire avant de commencer

- [`architecture/11-ops.md`](../architecture/11-ops.md)

## Périmètre

Lot transverse : pas de table ni d'endpoint métier.

## Étapes

Une étape = une PR. Commande : `/etape 0.6 <n>`.

### Étape 1 · Journaux

pino JSON sur la sortie standard (`pino-pretty` en local) avec `requestId`, `traceId`, `associationId`, utilisateur pseudonymisé (HMAC) ; liste de champs masqués (mot de passe, code, téléphone, jetons). Destination configurable ; l'envoi vers Logstash (ELK existant) est activé au lot 7.1.

**Vérification :** Test : un journal de connexion ne contient ni mot de passe ni téléphone en clair

### Étape 2 · Métriques

`/metrics` Prometheus (protégé, réseau interne) : RED par route, files BullMQ, âge de l'outbox ; tableau Grafana « Santé API » versionné dans `infra/grafana/` (importé au lot 7.1).

**Vérification :** En local, `/metrics` expose les séries RED, BullMQ et outbox ; le JSON du tableau est valide

### Étape 3 · Traces et erreurs

OpenTelemetry (HTTP, pg, ioredis, BullMQ), exportateur configurable (aucun ou console en local, Collector au lot 7.1) ; SDK GlitchTip front et back avec version et filtrage des données personnelles, **inactif sans DSN**.

**Vérification :** Test : une erreur provoquée en local est journalisée avec son `requestId` et son `traceId` ; sans DSN, aucun envoi

## Définition de fini

- [ ] Une erreur provoquée en local se retrouve dans les journaux avec `requestId` et `traceId`
- [ ] Aucune variable d'observabilité externe requise pour démarrer en local
- [ ] `pnpm verify` vert en CI
- [ ] Rien de simulé ajouté
- [ ] Aucune table sans politique RLS
- [ ] Démonstration en local
- [ ] `docs/progress.md` mis à jour (`/fin-lot 0.6`)
