## Périmètre

Lot transverse : pas de table ni d'endpoint métier.

## Étapes

Une étape = une PR. Commande : `/etape 0.6 <n>`.

### Étape 1 · Journaux

pino JSON avec `requestId`, `traceId`, `associationId`, utilisateur pseudonymisé (HMAC) ; liste de champs masqués (mot de passe, code, téléphone, jetons). Envoi vers Logstash (ELK existant).

**Vérification :** Test : un journal de connexion ne contient ni mot de passe ni téléphone en clair

### Étape 2 · Métriques

`/metrics` Prometheus (protégé, réseau interne) : RED par route, files BullMQ, âge de l'outbox ; tableau Grafana « Santé API » dans `infra/grafana/`.

**Vérification :** Tableau importable dans Grafana

### Étape 3 · Traces et erreurs

OpenTelemetry (HTTP, pg, ioredis, BullMQ) → Collector ; SDK GlitchTip front et back avec version déployée et filtrage des données personnelles.

**Vérification :** Erreur provoquée en recette visible dans GlitchTip avec son `requestId`

### Étape 4 · Disponibilité et alertes

Uptime Kuma sur `/health/ready` ; règles d'alerte Grafana de base → ntfy auto-hébergé.

**Vérification :** Arrêter l'api en recette déclenche une alerte

## Intégration front

- [ ] Aucune table sans politique RLS
