## Étapes

Une étape = une PR. Commande : `/etape 0.2 <n>`.

### Étape 1 · Socle de `packages/contracts`

Types communs : `Money` (`{amount: int, currency}`), `IsoDate`, `Instant`, `Uuid`, enveloppe de liste (`items`, `nextCursor`, `total`, `facets`), `Problem` (RFC 9457) ; `ErrorCode` généré depuis `docs/specs/errors.yaml` ; `EndpointId` généré depuis `docs/specs/endpoints.yaml` ; `Permission` et `Feature` depuis `permissions.yaml` et `features.yaml`.

**Vérification :** Script `pnpm --filter contracts gen` régénère ces unions ; un test échoue si un code YAML manque dans le TS

### Étape 2 · Schémas par espace — public, auth, plateforme

Pour chaque endpoint des groupes `sys`, `auth`, `pub`, `pf`, `as.resets`, `pf.resets` : schémas Zod de requête (path, query, body) et de réponse, déduits des fiches écran de `docs/ui/public.md` et `docs/ui/super-admin.md`. Registre `endpoints.ts` : `{ id, method, path, request, response, errors, flags }`.

**Vérification :** Chaque id de `endpoints.yaml` de ces groupes a une entrée ; `pnpm --filter contracts test` vert

### Étape 3 · Schémas — gestionnaire

Groupes `as`, `pr`, `en`, `mb`, `lg`, `rp`, `ct`, `im`, `rm`, `tm`, `bl`, `bk`, `dev` à partir de `docs/ui/manager.md`. Inclure `handoff` (code + message prêt) dans les réponses d'inscription et de régénération de code.

**Vérification :** Idem

### Étape 4 · Schémas — souscripteur et commun

Groupes `me*`, `nt`, `fl`, `psp` à partir de `docs/ui/subscriber.md`.

**Vérification :** Test : les 110+ ids de `endpoints.yaml` sont tous dans le registre, aucun en trop

### Étape 5 · OpenAPI et client

Génération OpenAPI 3.1 depuis le registre (zod-openapi) dans `packages/contracts/openapi.json` ; client typé `packages/api-client` (fetch, `Idempotency-Key` et `If-Match` automatiques selon les drapeaux, erreurs `Problem` typées). Page de doc interne (Scalar) servie par l'api en dev.

**Vérification :** `oasdiff` branché en CI contre `main` ; changement cassant → PR rouge

### Étape 6 · `packages/domain` : argent et identifiants

`Money` (entiers sûrs, addition, comparaison, jamais de flottant), `formatMoney` (U+202F et U+00A0), `newId()` UUID v7.

**Vérification :** Vecteurs `docs/specs/test-vectors/money.json` passent à l'identique

### Étape 7 · `packages/domain` : échéancier

`generateSchedule()` exactement selon `domain-rules.md`.

**Vérification :** Les 15 cas de `schedule.json` passent (sorties et codes d'erreur identiques) ; propriété fast-check : dates strictement croissantes, jamais avant `enrolledFrom`

### Étape 8 · `packages/domain` : répartition et statuts

`proposeAllocation()`, `validateAllocation()`, `installmentStatus()`, `lateSince()`, `memberStanding()`.

**Vérification :** Vecteurs `allocation.json`, `validation.json`, `status.json` ; propriétés sur 10 000 cas : Σ = montant, aucune allocation > reste, ordre respecté, `validateAllocation(proposeAllocation(x))` toujours ok

## Intégration front

- Aucune : le branchement du front (types, `formatFCFA` → `formatMoney`, aperçu d'échéancier, compteur « Reste à répartir ») est fait au lot 0.3.
- Pour écrire les schémas, lire aussi les types V0 (`frontend/types/`) et `docs/api-v0.md` : ils montrent les champs réellement affichés. Tout champ utile de la V0 absent de `endpoints.yaml` est signalé (ne pas l'ajouter en silence).
