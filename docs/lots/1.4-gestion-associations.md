## Étapes

Une étape = une PR. Commande : `/etape 1.4 <n>`.

### Étape 1 · Lecture plateforme

`pf.asso.list`, `pf.asso.get` (profil, abonnement, quotas, gestionnaires) ; chaque lecture plateforme est auditée.

**Vérification :** Tests de permission

### Étape 2 · Modification

`pf.asso.patch` avec `If-Match`.

**Vérification :** `version_conflict` testé

### Étape 3 · Suspension

`pf.asso.suspend` (suspend / reactivate) : statut, liste noire Redis, sessions des gestionnaires coupées, `association_suspended` sur toute requête.

**Vérification :** Un gestionnaire connecté reçoit 403 à la requête suivante

### Étape 4 · Changement de plan

`pf.asso.plan` avec date d'effet ; refus si l'usage dépasse les nouveaux quotas.

**Vérification :** `quota_exceeded` testé

### Étape 5 · Réinitialisations des gestionnaires

`pf.resets` : liste des demandes de gestionnaires, émission d'un code 6 chiffres affiché une fois avec message prêt.

**Vérification :** Parcours : demande d'un gestionnaire → code émis par le super-admin → nouveau mot de passe

### Étape 6 · Tableau de bord

Vues matérialisées (demandes en attente, associations actives, répartition par plan) + tâche `stats.refresh` ; `pf.dashboard`.

**Vérification :** Temps de réponse < 300 ms
