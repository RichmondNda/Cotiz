## Étapes

Une étape = une PR. Commande : `/etape 2.4 <n>`.

### Étape 1 · Tables

`payments`, `allocations` avec politiques, contraintes et trigger différé de `schema.sql`.

**Vérification :** Porter les scénarios 4 et 5 du test de fumée

### Étape 2 · Paiements d'amorçage

Commande de seed qui crée des déclarations réalistes (Moussa : 75 000 F sur 3 échéances ; Jean : partiel) pour tester avant l'espace souscripteur.

**Vérification :** `pnpm db:seed:demo`

### Étape 3 · Grille

`lg.grid` : membres × échéances, pagination par curseur, filtres, statuts calculés par `installmentStatus()` ; `lg.inst`.

**Vérification :** Grille 200 × 24 < 500 ms (k6)

### Étape 4 · File et détail

`lg.pay.list` (pending par défaut, facets), `lg.pay.get` (ETag, répartition proposée, preuve via `fl.get`).

**Vérification :** Tests

### Étape 5 · Validation — tests d'abord

Écrire d'abord les tests : nominal, répartition ajustée, montant reçu différent, `allocation_mismatch`, `allocation_exceeds_remaining`, deux validations concurrentes, `version_conflict`, isolation.

**Vérification :** Tests rouges

### Étape 6 · Validation — implémentation

`lg.pay.validate` : transaction de architecture/04 §4.5 : verrous ordonnés, `validateAllocation()`, allocations confirmées, échéances recalculées, verrouillage des conditions du projet, audit, `payment.validated`.

**Vérification :** Tests verts ; 100 000 cas aléatoires : soldes recalculés depuis les allocations = soldes stockés

### Étape 7 · Rejet et annulation

`lg.pay.reject` (motif) ; `lg.pay.revert` (auteur, 10 min, compensatoire).

**Vérification :** Une annulation restitue exactement l'état antérieur (comparaison avant/après)

### Étape 8 · Statuts quotidiens

Tâche `installments.refresh-statuses` par fuseau : `due`, `late`, `late_since`, événements regroupés.

**Vérification :** Test avec horloge simulée

## Intégration front

- Grille, panneau échéance, file de validation, détail avec répartition modifiable, toast d'annulation 10 s, message `payment_already_reviewed`.
- Basculer les endpoints du lot avec `/bascule <id>` : `lg.grid`, `lg.inst`, `lg.pay.list`, `lg.pay.get`, `lg.pay.validate`, `lg.pay.reject`, `lg.pay.revert`.
