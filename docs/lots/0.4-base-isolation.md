## Objectif

Prouver dès le départ qu'une association ne peut jamais lire les données d'une autre.

## Étapes

Une étape = une PR. Commande : `/etape 0.4 <n>`.

### Étape 1 · Drizzle et rôles

`packages/db` : Drizzle configuré, dossier `migrations/` en SQL versionné ; migration 0000 : extensions (`citext`, `pg_trgm`), fonctions `app_association_id()`, `app_user_id()`, `app_space()`, rôles et droits de base (voir fin de `schema.sql`). Connexion api : `cotiz_app` via PgBouncer ; migrations : `cotiz_migrator`.

**Vérification :** `pnpm db:migrate` sur une base vide passe ; `cotiz_app` n'a pas BYPASSRLS

### Étape 2 · Contexte tenant côté API

`src/shared/tenant-context` : `TenantContextInterceptor` ouvre la transaction, pose `SET LOCAL` à partir du jeton et de `{aid}`, rend `tx` disponible (AsyncLocalStorage). Aucun autre chemin d'accès à la base (règle dependency-cruiser : seul `shared/tenant-context` importe le client).

**Vérification :** Test : une requête sans contexte voit 0 ligne

### Étape 3 · Contexte côté worker

`withTenantContext({associationId, userId, space}, fn)` pour les tâches ; `space = 'system'` réservé au worker.

**Vérification :** Test : impossible d'utiliser `system` depuis un contrôleur HTTP (garde)

### Étape 4 · Gabarit RLS et garde-fou

Helper de migration `enableTenantRls(table)` qui produit `ENABLE`, `FORCE` et `tenant_isolation`. Test « méta » qui interroge `pg_policies` : toute table avec une colonne `association_id` NOT NULL doit avoir `tenant_isolation` et `FORCE ROW LEVEL SECURITY`.

**Vérification :** Le test échoue si on crée une table tenant sans politique (le vérifier une fois)

### Étape 5 · Harnais d'isolation

`backend/test/isolation/` : fabrique de deux associations (A, B) avec données, utilitaire `asManagerOf(B)` et `asSubscriber(x)` ; porter `docs/specs/rls-smoke-test.sql` en Vitest + Testcontainers.

**Vérification :** Suite verte ; retirer une politique la fait échouer

### Étape 6 · Colonnes communes

Helpers Drizzle : `id` UUID v7 applicatif, `createdAt`, `updatedAt`, `version` ; utilitaire de verrou optimiste (`updateWithVersion`) qui lève `version_conflict`.

**Vérification :** Test : deux mises à jour concurrentes avec la même version → une seule réussit
