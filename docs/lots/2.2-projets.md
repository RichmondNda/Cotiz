## Étapes

Une étape = une PR. Commande : `/etape 2.2 <n>`.

### Étape 1 · Tables

`projects`, `project_payment_methods`.

**Vérification :** Tests d'isolation

### Étape 2 · CRUD et aperçu

`pr.list` (facets), `pr.create` (quota), `pr.get` (ETag), `pr.preview` via `generateSchedule()`.

**Vérification :** Aperçu front et back identiques sur 1 000 projets aléatoires (fast-check)

### Étape 3 · Modification et verrouillage

`pr.patch` avec `If-Match` ; refus des champs financiers si `financial_terms_locked_at` (`financial_terms_locked`).

**Vérification :** Test sur un projet verrouillé

### Étape 4 · Cycle de vie

`pr.lifecycle` : publish (→ enrolling), close, duplicate ; `pr.delete` (brouillon seulement) ; tâche `projects.activate`.

**Vérification :** Transitions interdites → `invalid_state`

### Étape 5 · Vue d'ensemble

`pr.overview` : attendu, encaissé, retards, prochaine échéance (lit les échéances ; 0 avant le lot 2.3).

**Vérification :** Réponse conforme

## Intégration front

- Liste, assistant de création avec aperçu en direct, paramètres avec cadenas, vue d'ensemble.
- Basculer les endpoints du lot avec `/bascule <id>` : `pr.list`, `pr.create`, `pr.preview`, `pr.get`, `pr.patch`, `pr.lifecycle`, `pr.delete`, `pr.overview`.
