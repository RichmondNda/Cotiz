## Étapes

Une étape = une PR. Commande : `/etape 0.5 <n>`.

### Étape 1 · Outbox

Tables `outbox_events` et `audit_logs` (migration d'après `schema.sql`) ; `OutboxService.publish(tx, event)` ; relais dans le worker (`SELECT … FOR UPDATE SKIP LOCKED`, BullMQ `events`, `published_at`) ; enregistrement des consommateurs par type ; déduplication `{eventId}:{consumer}`.

**Vérification :** Test : un événement relayé deux fois n'est consommé qu'une fois ; transaction annulée → aucun événement

### Étape 2 · Audit

`@Audited(action)` sur les cas d'usage : acteur, association, entité, avant/après (champs modifiés seulement), `requestId`, IP. Droits : `cotiz_app` ne peut ni UPDATE ni DELETE `audit_logs`.

**Vérification :** Test : tentative de DELETE → erreur `append_only`

### Étape 3 · Stockage

Table `files` (clés étrangères vers `users` et `associations` ajoutées aux lots 1.1 et 1.2) ; `StorageService` (client S3 vers MinIO) : URL de dépôt présignée (taille et type imposés, 5 min, `quarantine/`), finalisation, URL de lecture signée 5 min. Endpoints `fl.upload`, `fl.get`.

**Vérification :** Test d'intégration avec MinIO en conteneur : dépôt direct puis lecture par URL signée

### Étape 4 · Analyse des fichiers

File `files` du worker : octets magiques (`file-type`), ClamAV (`clamscan` via `clamd` TCP), EXIF supprimé (sharp), SHA-256, miniature, déplacement ; `scan_status`.

**Vérification :** Fichier EICAR → `infected` et `file_not_clean` ; PDF sain → `clean` en < 2 s

### Étape 5 · Transverse HTTP

Filtre d'exceptions → `application/problem+json` avec `code` ; `X-Request-Id` ; limitation de débit Redis (par IP, utilisateur, association) ; intercepteur `Idempotency-Key` (réponse mémorisée 24 h, `idempotency_key_reused`) ; `ETag`/`If-Match`.

**Vérification :** Tests unitaires de chaque intercepteur

### Étape 6 · Tâche housekeeping

Tâche planifiée avec verrou : fichiers orphelins en `quarantine/` > 24 h, clés d'idempotence expirées.

**Vérification :** Test : deux workers → une seule exécution
