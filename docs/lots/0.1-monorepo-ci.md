## Étapes

Une étape = une PR. Commande : `/etape 0.1 <n>`.

### Étape 1 · Initialiser le monorepo

Workspace pnpm + Turborepo à la racine : `pnpm-workspace.yaml` avec `frontend` (Nuxt 4 **existant**, on ne le déplace pas), `backend` (NestJS, vide jusqu'ici) et `packages/{contracts,domain,api-client,db,pdf-templates,config}` vides avec `package.json` et `tsconfig` (les `CLAUDE.md` de `packages/contracts`, `domain` et `db` existent déjà). Le front passe de npm à pnpm : supprimer `frontend/package-lock.json`, un seul `pnpm-lock.yaml` à la racine ; ses scripts (`dev`, `lint`, `typecheck`, `test`, `e2e`, `capture`…) restent inchangés et s'appellent par `pnpm --filter frontend <script>`. Node 22 LTS fixé (`.nvmrc`, `engines`).

**Vérification :** `pnpm install && pnpm build` passe à la racine ; `pnpm --filter frontend lint typecheck test` restent verts

### Étape 2 · Configuration partagée

`packages/config` : ESLint (flat config), Prettier, `tsconfig.base.json` strict (`noUncheckedIndexedAccess`) pour `backend` et `packages/*` ; le front garde `@nuxt/eslint` et sa config (pas de Prettier sur `frontend/`, pour ne pas reformater la V0). Husky + lint-staged ; commitlint (Conventional Commits).

**Vérification :** `pnpm lint && pnpm typecheck` passent

### Étape 3 · Script `pnpm verify`

Script racine qui enchaîne : lint, typecheck, tests unitaires (front, back, paquets), `node tools/check-docs.mjs` (déjà dans `tools/` ; ajouter `yaml` en dépendance de développement à la racine). Il grossira à chaque lot (isolation, contrats, mocks).

**Vérification :** `pnpm verify` passe

### Étape 4 · Environnement local

`infra/compose/local.yml` : PostgreSQL 16, PgBouncer (transaction), Redis 7, MinIO (+ création des 5 compartiments), Gotenberg, ClamAV. `pnpm dev` démarre api, worker et web (le front garde ses mocks Nitro).

**Vérification :** `docker compose -f infra/compose/local.yml up -d` puis `pnpm dev` : web sur :3000, api sur :4000

### Étape 5 · Squelette NestJS

`main.ts` et `worker.ts` ; configuration validée au démarrage par Zod (`src/config.ts`, échec explicite si une variable manque) ; `sys.health` : `GET /api/v1/health/live` et `/health/ready` (vérifie PostgreSQL, Redis, MinIO).

**Vérification :** Test d'intégration : `/health/ready` renvoie 200 avec les trois services, 503 si Redis est arrêté

### Étape 6 · CI GitHub Actions

Faire évoluer `.github/workflows/ci.yml` (existant : lint, typecheck, tests, build, contrat d'API V0, parcours e2e/cohérence/a11y du front) : install pnpm (cache pnpm, `pnpm-lock.yaml`), `pnpm verify`, build des deux apps, `pnpm audit --prod`, Trivy sur les Dockerfiles ; garder le job « parcours » du front. Dockerfiles multi-étapes pour `web` et `api` (même image pour api et worker).

**Vérification :** Une PR de test déclenche la CI complète en < 8 min

### Étape 7 · Recette Dokploy

`infra/compose/staging.yml` ; webhook Dokploy appelé à la fusion sur `main` ; variables secrètes dans Dokploy ; domaine de recette derrière Traefik.

**Vérification :** Fusion sur `main` → `/health/ready` de recette répond 200

## Intégration front

- `frontend` membre du workspace ; variables `NUXT_API_ORIGIN` (NestJS, `http://localhost:4000`) et `NUXT_MOCKS=1` par défaut en local et recette (utilisées par le proxy de bascule, lot 0.3).
- Polices Poppins et Inter auto-hébergées via `@fontsource` : retirer le chargement Google Fonts de `frontend/nuxt.config.ts` (`app.head`) ; vérifier avec `/verifier-ecran` qu'aucun rendu ne change.
- Basculer les endpoints du lot avec `/bascule <id>` : `sys.health`.
